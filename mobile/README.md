# ClickFix mobile

The agent app for ClickFix: sign in (e-mail + password with 2FA, or a
6-digit e-mail code), pick the organization, work the inbox (views, status
tabs, unread / SLA / priority filters, search, SLA countdowns, live updates),
open a conversation and reply or leave an internal note with photos, camera
shots and files (voice messages play inline), assign / take, change status,
priority or snooze, see the contact, company and SLA clocks, keep writing
offline (a send queue delivers when the phone is back online), approve a web panel sign-in by scanning its
QR, get push notifications for mentions and assignments, and manage the
profile (theme, language, notifications, legal pages, account deletion).

Expo SDK 58, React Native 0.88, expo-router (native tabs), Uniwind
(Tailwind 4), TanStack Query (persisted), zustand, i18next. The structure is
ported from `takwim-app-go/mobile` (same boilerplate family); the code input
and QR approval from `olexfilms-ecosystem/mobile`, the Centrifugo driver from
`otopoly-mobile-app`. No UI framework: the primitives in `src/ui` are built on
React Native and the brand tokens (`docs/brand.md`: kit black, paper, signal
green `#03FF13`; Geist for text, Space Grotesk for titles). The app icon is
the kit's green tile (`frontend/src/assets/brand/clickfix-tile-green.svg`).

It uses the same `/v1` API as the panel (`backend/docs/openapi.yaml`), with its
own Bearer token pair, through the panel's passthrough route
`/api/mobile/v1/*` (`frontend/src/lib/server/mobile-proxy.ts`).

## Run

```bash
cd mobile
cp .env.example .env.local      # EXPO_PUBLIC_API_URL=<panel origin>/api/mobile
npm install
npx expo start                  # then press i / a for a development build
```

SDK 58 needs a development build (`npx expo run:ios` / `run:android`, or
`npx eas-cli@latest build --profile development`). `ios/` and `android/` are
generated by prebuild (CNG) and never committed; native settings live in
`app.json`.

## Structure

```
src/
  app/                 expo-router routes, one-line files
    (public)/          sign-in (e-mail + password + 2FA), code (e-mail code step)
    (app)/             signed in
      (org)/           needs an active organization
        (tabs)/        Inbox, Contacts, Agenda, Notifications, More (native tabs, at most five)
          more/        hub: search, agenda, video calls, team status, team chat, on-call,
                       reports, engineering, incidents, channels, members, AI, billing, settings
        conversation/[uuid]   timeline + composer (split view beside the list on tablets)
        search        global search + knowledge base (from the Inbox / Contacts headers and More)
        contact/ company/ article/ knowledge/ side-conversation/ team-chat/ engineering/
        appointment/ video/
      organizations    organization picker (after sign-in, and to switch)
      qr-scan, qr-login/[id]  approve a web panel sign-in
      delete-account   in-app account deletion
  core/                no UI: API client, session, permissions, i18n, formatting, OTA
  features/            screens and hooks, one folder per area
    auth/ inbox/ contacts/ search/ knowledge/ notifications/ team/ reports/
    engineering/ incidents/ admin/ more/ qr-login/ push/ realtime/ settings/ shell/
    guides/ assistant/ feedback/   coach marks, ClickFix Asistan, shake to send feedback
  ui/                  design system (tokens in src/global.css mirror the panel theme)
```

Rules:

- Cached data renders first and refreshes in the background (`staleTime`
  15–30 s, cache kept 7 days on disk, cleared on a new app version).
- An action the member's role cannot use is hidden (`useCan`, slugs in
  `src/core/auth/permissions.ts`); the API still enforces every one.
- Every string through i18n, Turkish first, English complete. Inbox labels,
  channel names and API error codes come from the panel's catalogs
  (`frontend/src/locales/*/{inbox,channels,errors,notifications}.json`), so web
  and mobile say the same thing.
- Colors only through theme classes (`bg-card`, `text-muted-foreground`, ...).
  Signal green is a fill (`bg-signal`, unread badges, the focus ring); green
  text uses `text-signal-text` (`Text tone="signal"`).
- Type is one family per weight: `font-sans-medium`, `font-sans-semibold`,
  `font-sans-bold`, `font-display` (Space Grotesk 600), `font-display-bold`;
  never `font-semibold`, which custom fonts ignore.
- Icons through `<Icon name=… />` (`src/ui/icons.ts`): SF Symbols on iOS,
  Material Symbols on Android, Lucide as the fallback; a new concept needs
  `sf`, `md` and `lucide`, then `npm run icons:gen`.
- Forms keep the focused field and the action above the keyboard
  (react-native-keyboard-controller); the conversation composer rides on it.

## Backend contract

Feature parity with the web panel is tracked in `docs/mobile/parity.md`.

- AI copilot (composer ✨): `POST /v1/tenant/conversations/{uuid}/copilot`
  (`suggest_reply`, `summarize`, `translate` with `locale`, `shorten`,
  `rewrite`; needs `tenant.conversations.reply`). Results are shown first and
  only go into the composer (or an internal note) on the agent's tap; 429 =
  AI credits used up, 503 = provider down.
- Presence: header dot in the inbox and the settings card (`/v1/tenant/presence/me`,
  heartbeat); "My shift" reads `/v1/tenant/teams?member={me}` working hours.
- Help (CF-142, contract from CF-141; details and guide target ids in
  `docs/mobile/guides.md`): coach-mark guides (`/v1/tenant/guides`,
  `/guides/setup`, `/guides/{key}/progress`, `/guides/reset`), ClickFix
  Asistan (`/v1/tenant/assistant/*`) and shake to send feedback
  (`expo-sensors` + `react-native-view-shot`, then attachments upload and
  `POST /v1/tenant/product-feedback`). These routes use the generated
  OpenAPI client and schemas; a 404 hides the feature on older servers.
- Security: biometric app lock (expo-local-authentication; on launch and after
  0/1/5/15 min away; stored per phone in the kv-store), sessions and devices
  (`/v1/auth/sessions`, revoke one / `revoke-others`).

- Sign-in: `POST /v1/auth/login` (with `totp_code` after `MFA_REQUIRED`), or
  `POST /v1/auth/email-code/request` → `/v1/auth/email-code/verify`.
  `POST /v1/auth/refresh` (rotation; one shared refresh for parallel 401s),
  `POST /v1/auth/logout`, `GET /v1/auth/me` (memberships and their
  `tenant.*` permissions).
- Tenant calls send `X-Organization: <slug>` (picked organization).
- Every request sends `X-App-Version` and `Accept-Language`.
- Inbox: `/v1/tenant/conversations` (+ `/counts`, `/agents`, `/{uuid}`, `/{uuid}/messages`,
  `/{uuid}/read`, `/{uuid}/sla`, `/{uuid}/messages/{message}/retry`, `PATCH /{uuid}`),
  `GET /v1/tenant/contacts/{uuid}` (with `tenant.contacts.read`).
- Files: the composer uploads to `POST /v1/tenant/attachments` (multipart,
  `tenant.attachments.write`) and sends the uuids with the message. The
  timeline loads images and audio from the API's `download_url` /
  `thumbnail_url` with the Bearer and `X-Organization` headers
  (`mediaSource`), and opens other files through
  `POST /v1/tenant/attachments/{uuid}/signed-url`. No storage keys in the app.
- Send queue (`src/features/inbox/outbox.ts`): replies and notes are written
  to the kv-store before the first try and keep their `client_id`, so a lost
  answer never stores a message twice. Network errors, 408 / 429 / 5xx wait
  (backoff, network change, foreground, next launch); other 4xx fail the
  bubble with the API's error and keep it in the queue until the agent taps
  "Tekrar dene" or "Sil". Composer drafts are kept per conversation
  (`drafts.ts`). Sign-out empties the queue and the drafts.
- Live: `POST /v1/realtime/connection-token` and `/subscription-token`, then
  the `inbox:{org_uuid}` channel (needs `tenant.conversations.read`). The
  socket URL is the token's `ws_url` (`EXPO_PUBLIC_REALTIME_URL` overrides it;
  a loopback `ws_url` behind a remote API is ignored, `ws://` is upgraded to
  `wss://` behind https). The handshake sends the panel origin
  (`EXPO_PUBLIC_WEB_URL`) as `Origin`, because Centrifugo's `allowed_origins`
  lists the panel origins only. Realtime never gates sending: while the socket
  is down the open screens poll (conversation 10 s, list 30 s).
- Connection: requests never send cookies (`credentials: 'omit'`), give up
  after 30 s (uploads 180 s) and report transport failures as
  `NETWORK_ERROR` / `TIMEOUT` (status 0) or `INVALID_RESPONSE` (502, a body
  that is not JSON). "Offline" is the OS's `isConnected` only; "server
  unreachable" is learned from real requests (`useConnection`).
- QR sign-in: the panel's QR encodes `{panel}/login/qr/{session_id}`;
  `GET /v1/auth/qr/sessions/{id}` → `/approve` or `/reject`.
- Tokens live in SecureStore; everything else in the expo-sqlite kv-store.
- Push: after sign-in the app asks for the notification permission and sends
  its Expo token to `POST /v1/push-devices`; every in-app notification is
  mirrored. Sign-out deletes the token first. Push `data` carries `url`,
  `organization` (slug), `organization_uuid` and, for conversations,
  `conversation_uuid`; `badge` is the unread count. A tapped push switches to
  its organization first and opens the conversation (`src/features/push/links.ts`).
  Conversation pushes use the `conversation` category: "Reply" sends the text
  typed on the notification through the inbox send queue, "Open" opens it
  (`quick-reply.ts`; Android delivers actions to a killed app through the
  background task defined in `index.ts`). Preferences (push on/off, per-event
  push, quiet hours): `/v1/notification-preferences` (+ `/events`).

## Release (owner, once)

Identifiers are final: iOS `com.getclickfix.app` (widgets
`com.getclickfix.app.widgets`, App Group `group.com.getclickfix.app`), Android
`com.getclickfix.app`. `app.json` has no EAS project id or update URL yet. CI's
`mobile-release` job skips until `EXPO_TOKEN` is set **and** `app.json` has
`extra.eas.projectId`.

1. `npx eas-cli@latest init` in `mobile/` (writes `owner` and
   `extra.eas.projectId`), then `npx eas-cli@latest update:configure` (writes
   `updates.url`). Commit both.
2. The identifiers above are set in `app.json` (`ios.bundleIdentifier`,
   `android.package`); `scheme` is `clickfix`.
3. EAS environment variables per profile (`eas env:create`):
   `EXPO_PUBLIC_API_URL=https://<panel host>/api/mobile` and
   `EXPO_PUBLIC_WEB_URL=https://<panel host>`.
4. iOS: create the App Store Connect record for the bundle id, put its
   `ascAppId` (and `appleTeamId`) under `submit.production.ios` in `eas.json`,
   and let `eas credentials -p ios` create the certificate and an ASC API key.
5. Android: create the Play Console app, upload a service account key with
   `eas credentials -p android`. The first Android upload is done by hand in
   Play Console; after that `eas submit` works.
6. Push (`expo-notifications`; needs the project id from step 1):
   - iOS: upload an APNs key (`.p8`) in `eas credentials -p ios` → Push
     Notifications.
   - Android (FCM V1): add an Android app in Firebase with the package, put
     `google-services.json` in `mobile/` and `"googleServicesFile":
     "./google-services.json"` under `android` in `app.json`; upload the
     Firebase service account JSON with `eas credentials -p android` → FCM V1.
     Never commit the service account key.
   - Server: optionally turn on "Enhanced push security" for the Expo project
     and set its access token as `EXPO_ACCESS_TOKEN` for the API and worker.
7. GitHub: add the `EXPO_TOKEN` repository secret (an Expo robot token).
   From then on every green push to `main` that touches `mobile/` ships: an
   OTA update when the native fingerprint matches the latest store build, a
   store build with auto-submit otherwise.
8. Store listing: privacy policy `https://<panel host>/legal/privacy`, terms
   `/legal/terms`. In-app account deletion (Apple 5.1.1(v)) is in
   Settings → Delete account. App Review needs a demo account with one
   organization and a few conversations; e-mails in `AUTH_REVIEW_ACCOUNTS`
   get a fixed e-mail code.

Versions: `version` in `app.json` is the marketing version; build numbers live
on EAS (`appVersionSource: remote`, `autoIncrement`).

OTA: JS-only changes ship with `eas update --channel <profile>`. The runtime
version uses the `fingerprint` policy, so an update only reaches binaries with
the same native code. The app checks on launch and on foreground (at most every
15 min) and shows a "new version ready" bar.

Links: `clickfix://qr-login/<id>` and `clickfix://conversation/<uuid>` open
today. For panel https links to open the app, associate the domain at release
(iOS `associatedDomains` + `apple-app-site-association`, Android
`intentFilters` + `assetlinks.json`); `src/app/+native-intent.tsx` already maps
`/login/qr/{id}` and `/inbox?c={uuid}`.
