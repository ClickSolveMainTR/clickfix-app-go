This guide covers, in the order the **Setup** wizard in the panel follows, everything you write to connect your own product to ClickFix. Each step has its own page, and each step has five samples: the **widget** in the browser (JavaScript), **Node.js** (`@getclickfix/node`), **Go** (`github.com/ClickSolveMainTR/clickfix-sdks/go`), **PHP** (`clickfix/sdk`) and **curl**. The samples come from the `examples` folder of the public [`clickfix-sdks`](https://github.com/ClickSolveMainTR/clickfix-sdks/tree/main/examples) repository and are executed on every release; the code you see here is the code that passed. For complete, runnable applications (Express, Next.js, React Native, Flutter, Go, PHP, Laravel, curl) see the [`clickfix-examples`](https://github.com/ClickSolveMainTR/clickfix-examples) repository.

## Before you start [#before-you-start]

| You need                                    | Where                                         | Used for                                                                             |
| ------------------------------------------- | --------------------------------------------- | ------------------------------------------------------------------------------------ |
| **API key** (`cf_sk_…`)                     | Organization → API and automations → API keys | Every call from your server (`Authorization: Bearer`)                                |
| **Widget identity secret**                  | Web widget → Security → Identity verification | Computing `user_hash` (user + company id), server side only                          |
| **Widget id** (`WIDGET_ID`)                 | Web widget → Install                          | `widget.js` and the mobile webview URL                                               |
| **API channel instance and signing secret** | Channels → Add channel → API                  | Only when you connect your own chat app as a channel                                 |
| **App key** (mobile)                        | Web widget → Advanced → Mobile apps           | Only for apps calling the widget API without a webview (`@getclickfix/visitor-core`) |

The base URL is `https://api.getclickfix.com` (no `/v1` suffix). Writes require `Idempotency-Key`. Keys never reach the browser or the mobile app. Envelope, error codes and rate limits: [API](/docs/api?lang=en).

## The right setup order [#setup-order]

The **Setup** wizard in the panel has five steps; the pages of this guide follow the same order. Open each step in the panel first, then write its code.

| Wizard step               | In this guide                                                                                                                                                                                                                                                       | In the panel                                    |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| 1. Introduce the customer | [Identity verification](/docs/integration-guide/identity?lang=en), [external ids and company](/docs/integration-guide/contacts-companies?lang=en), [custom fields](/docs/integration-guide/custom-fields?lang=en), [events](/docs/integration-guide/events?lang=en) | Web widget → Security; Settings → Custom fields |
| 2. Connect your system    | [Connect your system](/docs/integration-guide/system-binding?lang=en)                                                                                                                                                                                               | Integrations → Connect your system              |
| 3. Teach the AI           | [Next steps](#next-steps)                                                                                                                                                                                                                                           | AI → Procedures                                 |
| 4. Knowledge base         | [Next steps](#next-steps)                                                                                                                                                                                                                                           | Knowledge base                                  |
| 5. Automation and SLA     | [Webhooks](/docs/integration-guide/webhooks?lang=en), [next steps](#next-steps)                                                                                                                                                                                     | Automation, SLA                                 |

The [API channel](/docs/integration-guide/api-channel?lang=en) and the [mobile webview](/docs/integration-guide/mobile?lang=en) are channel setup; do them after introducing the customer, before or after system binding.
